# v0.2 capability additions (schema 1)

All additions use the existing scan/parse/report pipeline and standard library.
Only Get operations are issued. Optional failures do not change the meaning of
FULL/PARTIAL: FULL is still basic device information plus profiles, not proof
that every optional capability query succeeded. Read each capability status.

## Profile-visible sources

`source_token` remains the legacy **configuration** token. `video_source_token`
is the real SourceToken from GetProfiles. New `source_configuration_name` is
that configuration's Name; `source_name_origin` is
`VideoSourceConfiguration.Name` (the same conceptual configuration is named
VideoSource inside Media2 Configurations). Missing values are null.

Profile token plus media generation identifies the association within the
selected service route. HTML shows both tokens and the configuration name's
origin. Names are not physical source names. No independent source enumeration,
unbound-source completeness claim or NVR classification is made.
`channel_count` and `channel_count_basis` retain the step 0–1 contract: count
known source tokens when any exist, otherwise count profiles. This legacy
summary is not a count of all physical inputs; missing associations remain
visible per profile, and cross-service source identity is not verified.

## Encoder options

Each profile has `encoder_options: {status, reason, data}`. Status is one of
`ok`, `unsupported`, `auth_blocked`, `failed`, `unqueried`. Failure or an unissued
query has null data, with a reason. Successful empty options have empty lists.
No profile limit or shared-configuration cache applies to options queries.
Missing encoder tokens are explicitly unqueried. Existing current codec, size,
fps and bitrate fields are independent of these declarations.

Data contains `encodings` and `declarations`. Each declaration has `encoding`,
`origin`, `resolutions`, `frame_rate_range`, `frame_rates_supported`,
`bitrate_range_kbps`, `gov_length_range`, `profiles_supported`, `quality_range`
and `encoding_interval_range`. Undeclared fields are null. Media1 ranges are
min/max objects; Media2 FrameRatesSupported is a floating point list, never
rounded to integers. Media2 GovLengthRange preserves its declared integer list.
Media1 base and Extension options are separate entries so conflicting values
are not silently merged. These declarations do not establish that all
encoding × resolution × frame-rate combinations are usable.

### D1 request conflict (deliberately unresolved)

Frozen D1 requires a Media2 GetConfiguration **wrapper element** inside
GetVideoEncoderConfigurationOptions. The official WSDL instead declares the
operation element with `type="tr2:GetConfiguration"`; that complex type has
ConfigurationToken and ProfileToken directly in its sequence. A type name does
not introduce a wrapper element.

[Official Media2 WSDL](https://www.onvif.org/ver20/media/wsdl/media.wsdl)

Per the task's stop condition, no Media2 options request is constructed or sent.
Each affected profile reports unqueried with a D1 conflict reason (or
auth_blocked if the credential gate has already closed). The Media2 response
parser and fractional-rate fixture are tested independently; this is not a
Media2 request end-to-end acceptance claim. Next step: maintainer revises D1 to
the direct-child shape, or supplies an authoritative schema/version requiring
the wrapper. Then add that request and its strict simulator assertion together.

## PTZ declarations and presets

`ptz.present/evidence` remain. New `ptz.nodes_status/nodes_reason` describe
GetNodes enumeration. `ptz.nodes` contains one record per known NodeToken:
`{token, status, reason, source, data}`. Complete GetNodes declarations are used
without another request; known missing/incomplete nodes get one GetNode each.
Missing optional FixedHomePosition or SupportedPresetTour does not trigger a
supplement. Enumeration failures do not hide already known profile NodeTokens.

Node data contains token/name, `maximum_number_of_presets`, `home_supported`,
`fixed_home_position` and `supported_preset_tour`. The latter is null if absent,
otherwise holds `maximum_number_of_preset_tours` and declared `operations`.
Missing declarations remain null; explicit false/zero stay false/zero. Failed
node queries have null data. No Home or tour operation is executed.

Each profile also has `ptz_node_status/ptz_node_reason` for its association and
`ptz_presets: {status, reason, data}`. Successful data has only `count` and
`names`; names can be null and duplicates are retained. Successful empty is
count 0 and names []; failures/unqueried are null data. Counts are per profile,
never summed into node totals. Preset capacity and actual counts are separate.
Preset tokens and coordinates are not exported. No GetConfiguration,
GetPresetTours, private tour queries or movement calls are made.

All new values pass through the existing final password scrub; HTML values
use the existing escaping helper. No raw SOAP is added to reports or logs.
The existing stream/snapshot URI limit remains separate from these unbounded
options, node and preset queries.
